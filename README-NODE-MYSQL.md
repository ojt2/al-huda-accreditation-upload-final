# منصة الاعتماد المؤسسي: Node.js + MySQL

## 1. إنشاء قاعدة البيانات

نفّذ ملف `schema.sql` داخل MySQL أو phpMyAdmin. ينشئ الملف قاعدة البيانات والجداول:

- حسابات الأدمن.
- حالة المنصة والتقييمات والمطابقة وخطة التحسين.
- ملفات المؤشرات المرفوعة.

## 2. إعداد الخادم

1. ثبّت Node.js على الاستضافة.
2. ارفع `index.html` و`server.js` و`package.json` و`schema.sql` ومجلد `assets` ومجلد `uploads` إلى مجلد المشروع.
3. انسخ `.env.example` إلى `.env` وعدّل بيانات MySQL.
4. نفّذ:

```bash
npm install
node server.js
```

ملف `.env` الموجود في الحزمة نموذج جاهز للتعديل. لا تعرضه للعامة ولا ترفعه إلى مستودع عام.

يفضل تشغيله خلف Nginx أو Apache مع HTTPS، أو باستخدام PM2:

```bash
npm install -g pm2
pm2 start server.js --name al-huda-accreditation
pm2 save
```

## 3. تسجيل الدخول

في أول تشغيل، إذا لم توجد حسابات، ينشئ الخادم حساب الأدمن من المتغيرين السريين `ADMIN_EMAIL` و`ADMIN_PASSWORD` في ملف `.env`. لا تضع هذه القيم داخل HTML أو تنشر ملف `.env`. ويمكن إضافة حسابات أدمن أخرى من داخل إعدادات المنصة.

## 4. الملفات

رفع الملف من بطاقة المؤشر يحفظ محتوى الملف نفسه داخل عمود `file_data` في جدول `indicator_files` داخل MySQL، ويحفظ بياناته الوصفية أيضاً. مجلد الرفع يستخدم مؤقتاً أثناء استقبال الملف ثم تُحذف النسخة المؤقتة، والضغط على بطاقة المؤشر يفتح الملف من API مرتبط بقاعدة البيانات.

## 5. الأمان

- لا تضع ملف `.env` أو كلمة مرور MySQL داخل المستودع العام.
- استخدم HTTPS.
- استخدم HTTPS حتى تعمل ملفات تعريف الارتباط الآمنة في الإنتاج.
- جلسات الدخول محفوظة في MySQL بدل التخزين المؤقت للذاكرة.
- محاولات الدخول محدودة تلقائيًا لمنع التخمين المتكرر.
- لا تفتح مجلد `uploads` للعامة؛ ملفات المؤشرات تمر عبر جلسة أدمن مصرح بها.
- اجعل مجلد `uploads` قابلاً للكتابة من Node.js فقط.
- غيّر `SESSION_SECRET` إلى قيمة عشوائية طويلة.
